# v1.3.0 Interview Story

## Summary

“I separated artifact creation from deployment. CI validates and publishes an immutable artifact, Git stores the desired state, and Argo CD reconciles that state with Kubernetes.”

## Points to demonstrate

- An AppProject limits the trusted repository, target namespaces, and resource kinds.
- One ApplicationSet generates Development, QA, and Production Applications.
- Development has automatic sync, pruning, and self-healing.
- QA and Production remain manually synchronized.
- Helm combines reusable environment sizing with GitOps image overrides.
- Promotion copies the exact OCI digest from Dev to QA to Production.
- A promotion cannot skip an environment.
- Drift is visible in every environment, but only Development self-heals automatically.
- Rollback is performed by reverting Git, not by making an undocumented live-cluster change.

## Real-world reasoning

The controls are intentionally asymmetric. Development optimizes feedback speed. QA and Production optimize review, risk control, and auditability.

## Honest boundary

The release contains production-style GitOps manifests and validation. A live deployment still requires a reachable registry image, cluster-specific access, Argo CD RBAC, and organization-specific approvals.
