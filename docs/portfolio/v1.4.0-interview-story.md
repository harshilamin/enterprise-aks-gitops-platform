# v1.4.0 Interview Story

## Summary

“I removed static cloud credentials from the workload. The pod uses a projected Kubernetes ServiceAccount token, AKS publishes the OIDC issuer, Microsoft Entra exchanges the token for a managed-identity token, and the Key Vault CSI provider mounts only the permitted secrets.”

## Design points

- No client secret is created.
- The ServiceAccount is annotated with identity and tenant identifiers.
- The pod has the required Workload Identity label.
- A federated credential trusts an exact namespace and ServiceAccount subject.
- Azure RBAC grants read-only `Key Vault Secrets User`.
- The chart renders a namespaced `SecretProviderClass`.
- Secrets are mounted as read-only files.
- The chart does not synchronize values into Kubernetes Secrets.
- Argo CD receives identifiers and object names only.
- Dev, QA, and Production can use separate identities and vaults.

## Operational controls

- Idempotent PowerShell and Bash bootstrap scripts
- GitOps values generator
- Six unit tests
- Three-environment Helm rendering
- Purpose-built manifest assertions
- Live verification that lists filenames without revealing values

## Honest boundary

This repository demonstrates the workload configuration and Azure bootstrap workflow. Production infrastructure ownership, private endpoints, Key Vault creation, diagnostics, and long-lived role assignments belong in Repository 1 Terraform.
