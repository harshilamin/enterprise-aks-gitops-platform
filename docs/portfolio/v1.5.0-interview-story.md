# v1.5.0 Interview Story

## Summary

“I instrumented a FastAPI workload with vendor-neutral OpenTelemetry, sent traces and metrics over OTLP to a hardened Collector, exposed metrics to Prometheus, provisioned Grafana dashboards, and implemented availability and latency SLO alerts.”

## Design choices

- Manual instrumentation keeps the behavior explicit and testable.
- Isolated providers avoid global state conflicts in tests.
- OTLP/HTTP simplifies application-to-Collector transport.
- The Collector separates instrumentation from backend selection.
- Prometheus scrapes the Collector rather than the application.
- Structured stdout logs carry trace correlation.
- Route templates prevent high-cardinality metric labels.
- Sampling is environment-specific and parent-based.
- Multi-window alerts reduce noise compared with a single threshold.

## Security and operations

- Non-root, read-only Collector container
- Application-to-Collector NetworkPolicy
- Monitoring-namespace-only metric scraping
- No Grafana password in Git
- No request bodies, credentials, or query strings in telemetry
- Manual synchronization for the cluster-wide monitoring stack

## Honest boundary

Traces use the Collector debug exporter in this release. The architecture is ready for a durable OTLP trace backend without changing application code.
